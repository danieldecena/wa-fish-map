# Washington Fishing Map: catch reports for Puget Sound rivers

Design spec, 2026-10-26. Scope is the published web page at
https://claude.ai/artifact/9oA145toRsmFcDYurdJbey, Map tab, Recent reports mode only.
The iOS app, `fisheries.json`, Typical season and Spawning are untouched.

## Why

Recent reports colours eight southwest Washington waters (Cowlitz, Lower Columbia, Lewis,
Wind, Klickitat, Drano Lake, Kalama, Washougal). Every other river is tappable but unrated
by design, so the map reads as mostly grey. The goal is to colour more rivers, starting
with Puget Sound, without ever guessing a rating.

## Decisions (agreed in brainstorming)

1. **Region first:** Puget Sound rivers: Skagit, Stillaguamish, Snohomish, Green, Puyallup,
   Nisqually.
2. **Catch quality only.** A river is coloured only when a dated source describes the
   fishing. No open/closed marking, no rating from rules, flows, forecasts or counts.
3. **Sources:** named, dated, linked reports from fishing shops, guides, guide services and
   agencies (for example The Avid Angler, The Guide's Forecast, Captain Experiences guide
   reports, WDFW written reports). Not social-media posts.
4. **Drawing:** pin plus coloured line, built from the tappable-river geometry
   (`rivers-tap.js`), because `geo.js` is generated by a tool that is not in this repo and
   must not be hand-edited.
5. **Home view:** Recent reports opens fitted to every report site.
6. **Entry age:** a new rating may be added only if its report is at most 14 days old on
   the day it is added. After that the existing 7-day rule dashes it as it ages.

## Not in scope

- Any automatic fetching or scraping of reports. Ratings are hand-written from a source.
- Changing the eight existing entries, or requiring sources on them (they predate the
  source rule and are grandfathered).
- Open/closed status marks, flow-based or count-based colour.
- Regions beyond Puget Sound (the mechanism works anywhere; adding them is a later data pass).
- Merging the page tab bar with the map control bar (a separate request).

## 1. Data: `reports.js`

A new river is one more entry in `SITES`, with the existing fields (`id`, `name`, `sub`,
`hl`, `reports` keyed by exact species name; each species `{ r, asOf, d, release?, phrase?, src }`)
plus three new site fields:

| field   | meaning |
|---------|---------|
| `tap`   | id of a river in `rivers-tap.js` (for example `skagit-river`). Its path is the highlighted line. |
| `ll`    | `[lat, lon]` of the pin, a named access point or reach on that river, written in the research note. |
| `added` | `YYYY-MM-DD`, the day the entry was added. Used only by the entry-age test. |

Rules for a new entry (on top of the README's existing ones: never invent a date, no date in
the prose, `slow` only from the source's own word kept in `phrase`):

- Every species report has `src: { label, url }`.
- `asOf` is at most 14 days before `added`.
- Wording to rating, from the source's own words: "hot", "excellent", "on fire" to
  `prime`; "good", "very good", "solid" to `good`; "fair", "some fish", "spotty" to `fair`;
  "slow", "poor", "tough" to `slow` with the phrase recorded. A report about rules, flows,
  trout, forecasts or effort with no catch read gives no rating.
- A river WDFW has closed for the species gets no rating for it, whatever a report says.
  Its WDFW notice still shows on the tappable river sheet.
- Species names are exact app names (`test/species-vocab.test.js` already enforces this).

## 2. Research note

Each data pass writes `docs/research/YYYY-MM-DD-puget-river-reports.md` in the shape of the
2026-10-18 Skagit and Puyallup coho notes: per river, the claim, the quote, the URL, the
date and a verdict. A river with no qualifying report gets a "Not added" line with the
reason (too old, no catch read, closed, trout only). An empty first batch is a valid outcome.

At design time the newest Puget freshwater salmon report found was The Avid Angler's
Skagit note of 2026-09-10, so the first batch is likely empty under the 14-day rule.

## 3. Drawing: `index.html`

- **Pin:** `D.pins[s.id]` when `geo.js` has it, else `s.ll` projected with the page's own
  `xy()`.
- **Line:** `D.hl[s.id]` when present, else the path of `RIVERTAP` river `s.tap`. Both are
  in the same viewport coordinates. Colour, casing, dashed-when-stale, release fade,
  selection and the hit path behave as for the eight. The report line sits above the
  invisible tappable layer, so a tap opens the report sheet.
- **Missing geometry:** a site whose `tap` does not resolve keeps its pin and draws no
  line. The test in section 5 fails the build first, so this is a guard, not a feature.
- **Home view:** in Recent reports, `homeBounds()` becomes the union of the southwest box
  and the bounding box of all report-site positions (with the existing margins). On phones,
  `homeFit()` already fits all `SITES`; that stays, and now includes new sites.
- **Wording:** "Southwest Washington" in the subtitle (two places) and the map's
  `aria-label` becomes "Washington" once any site lies outside the southwest box; until
  then the text is unchanged. README and the Recent reports description in
  `artifact.json`'s `what` follow when the first new site ships.

## 4. Unchanged behaviour

Rankings, the Rivers list, species dropdown, clusters (coloured only when every member
shares a rating), the stale-report notice and the phone report-age line, Week's
"Reported this week" (it reads `Reports.SITES`, so new sites appear there automatically),
and every rule that keeps counts and seasonal timing out of ratings.

## 5. Tests

- `test/reports.test.js`, for every entry that has `added`:
  - `src.label` and `src.url` present on every species report;
  - `tap` exists in `rivers-tap.js`;
  - `ll` lies inside the Washington box (`GEO.bounds.state` after projection);
  - `asOf` is at most 14 days before `added`, and not after it;
  - `slow` has a `phrase`.
  The eight existing entries have no `added` and are skipped by these checks. A self-check
  runs the rules against an in-test fixture entry so a rule that can never fail is caught.
- Baseline pins: the eight stay exact; any new site is checked against its own `ll`.
- Home view: the bounds logic moves into a pure `Reports.homeBox(sites, swBox)` in
  `reports.js` (which already runs in Node), and a test shows the result contains the
  southwest box and every site position.
- `check-week.mjs`: one case serves a fixture `reports.js` with a Puget site via
  `page.route`, at 390 and 1280 px, and checks the pin, its label, its line colour, and that
  the opening view contains it. This exercises the new drawing path while the real data has
  no new rivers.
